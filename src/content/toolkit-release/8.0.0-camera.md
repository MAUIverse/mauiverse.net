This release updates `CommunityToolkit.Maui.Camera` to .NET 11. 

It also enables [Runtime Async](https://learn.microsoft.com/dotnet/core/whats-new/dotnet-11/runtime#runtime-async) only on the `net11.0-windows` TFM. Runtime Async is not enabled on the Mono Runtime and is not recommended for any NuGet library that may be consumed by an app using the Mono Runtime.

We have removed code supporting the Tizen TFM as Tizen was no longer supported in .NET MAUI starting with .NET 10.

## Breaking Changes

The update to .NET 11 required us to modify some APIs and their underlying behavior. Please find the features you use, below, and update your apps accordingly.

<details><summary>All packages</summary>

<dl><dd>

<details><summary>API</summary>

- **Minimum OS versions in the API.** The `AppBuilderExtensions` classes declare `[SupportedOSPlatform]` iOS 15.0, Mac Catalyst 17.0 and Android 24.0 (MediaElement: Android 26.0), the .NET MAUI 11 minimums. Attributes that only restated a version below these minimums are removed or made versionless; this only relaxes the analyzer. Feature-specific changes are in the CameraView, FileSaver and FolderPicker, MediaElement, NavigationBar (Android), SemanticOrderView, and StatusBar and StatusBarBehavior sections.
- **No Tizen API surface.** The Tizen `[SupportedOSPlatform]` and `[UnsupportedOSPlatform]` attributes and the Tizen code paths are removed.

</details>

<details><summary>Setup</summary>

- **.NET 11 only.** The libraries target `net11.0` and its platforms. The minimum OS versions align with .NET MAUI 11's: iOS 15.0, Mac Catalyst 17.0 (macOS 14), Android 7.0 (API 24), Windows 10 1809 (10.0.17763)
- **Tizen is no longer supported.** The packages already shipped no Tizen target; .NET MAUI 11 dropped Tizen.

</details>

<details><summary>Smaller changes</summary>

- **Windows: the async methods of the `net11.0-windows` assemblies are runtime async.** No API or functional change: the compiler no longer generates async state machines for these methods (except `async void` ones), and the runtime handles their suspension instead.

</details>

</dd></dl>

</details>
