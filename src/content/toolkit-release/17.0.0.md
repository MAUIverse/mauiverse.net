This release updates `CommunityToolkit.Maui` to .NET 11. 

It also enables [Runtime Async](https://learn.microsoft.com/dotnet/core/whats-new/dotnet-11/runtime#runtime-async) only on the `net11.0-windows` TFM. Runtime Async is not enabled on the Mono Runtime and is not recommended for any NuGet library that may be consumed by an app using the Mono Runtime.

We have removed code supporting the Tizen TFM as Tizen was no longer supported in .NET MAUI starting with .NET 10.

We have also removed code supporting `CommunityToolkit.Maui.Maps`. See the [Release Notes for `CommunityToolkit.Maui.Maps v5.0.0`](https://github.com/CommunityToolkit/Maui/releases#release-5.0.0-maps) for more information.

## Breaking Changes

The update to .NET 11 required us to modify some APIs and their underlying behavior. Please find the features you use, below, and update your apps accordingly.

<details><summary>All packages</summary>

<dl><dd>

<details><summary>API</summary>

- **Minimum OS versions in the API.** The `AppBuilderExtensions` classes declare `[SupportedOSPlatform]` iOS 15.0, Mac Catalyst 17.0 and Android 24.0 (MediaElement: Android 26.0), the .NET MAUI 11 minimums. Attributes that only restated a version below these minimums are removed or made versionless; this only relaxes the analyzer. Feature-specific changes are in the CameraView, FileSaver and FolderPicker, MediaElement, NavigationBar (Android), SemanticOrderView, and StatusBar and StatusBarBehavior sections.
- **No Tizen API surface.** The Tizen `[SupportedOSPlatform]` and `[UnsupportedOSPlatform]` attributes and the Tizen code paths are removed.

</details>

<details><summary>Behavior</summary>

- **Converters use the culture the binding passes.** With no `ConverterCulture`, .NET MAUI passes `CultureInfo.CurrentUICulture`, as .NET MAUI 10 did.
  - These converters used the thread's `CurrentCulture` instead: `ColorToCmykStringConverter`, `ColorToHslStringConverter`, `ColorToHslaStringConverter`, `CompareConverter`, `IsInRangeConverter`, `ListToStringConverter`, `MathExpressionConverter` and `MultiMathExpressionConverter`.
  - Their output changes only when `ConverterCulture` is set or when an app's UI language differs from its regional format.
  - `TextCaseConverter` always used invariant casing instead, so its output also changes when the binding's culture is Turkish or Azerbaijani (see its section).
  - A `null` culture (calling a converter directly) keeps the previous behavior.
  - Each converter's section says what it does with the culture. `ColorToRgbaStringConverter`, `DateTimeOffsetConverter` and `DoubleToIntConverter` have separate changes, also in their sections.

</details>

<details><summary>Setup</summary>

- **.NET 11 only.** The libraries target `net11.0` and its platforms; .NET 10 apps should stay on the last .NET 10 releases (CommunityToolkit.Maui 15.x, CommunityToolkit.Maui.Camera 6.x, CommunityToolkit.Maui.MediaElement 10.x). The minimum OS versions are .NET MAUI 11's: iOS 15.0, Mac Catalyst 17.0 (macOS 14), Android 7.0 (API 24), Windows 10 1809 (10.0.17763); CommunityToolkit.Maui.MediaElement still requires Android 8.0 (API 26). .NET MAUI 11 itself no longer supports the older versions.
- **Tizen is no longer supported.** The packages already shipped no Tizen target; .NET MAUI 11 dropped Tizen.
- **Dependencies:** the libraries reference .NET MAUI 11 (`Microsoft.Maui.Controls` 11.0.0), and CommunityToolkit.Maui.Core references `System.Speech` 11.0.0 on Windows *(pending: RC versions until the last commit)*.

</details>

<details><summary>Smaller changes</summary>

- **Windows: the async methods of the `net11.0-windows` assemblies are runtime async.** No API or functional change: the compiler no longer generates async state machines for these methods (except `async void` ones), and the runtime handles their suspension instead.
- **Informational, from .NET MAUI 11:** on iOS and Mac Catalyst, .NET MAUI 11 skips animations while the system's Reduce Motion setting is on, so the toolkit's animations (`TouchBehavior`, `FadeAnimation`, the animation behaviors) finish at once for those users. The toolkit doesn't change this.

</details>

</dd></dl>

</details>

<details><summary>DoubleToIntConverter</summary>

<dl><dd>

<details><summary>Behavior</summary>

- Parses a string `ConverterParameter` with the invariant culture first, so `ConverterParameter=2.5` means 2.5 for every user, and falls back to the binding's culture, so `2,5` still works in comma-decimal cultures.
- A parameter with only `.` separators is now always a decimal: `1.000` under de-DE means 1 (it meant 1000).

</details>

</dd></dl>

<details><summary>FileSaver and FolderPicker</summary>

<dl><dd>

<details><summary>API</summary>

- The `[SupportedOSPlatform]` attributes `iOS14.0`/`MacCatalyst14.0` on `FileSaver` and `FolderPicker` are now `iOS`/`MacCatalyst` (see All packages).

</details>

<details><summary>Behavior</summary>

- **On Windows (.NET 11):**
  - With no visible app window they fail with `FileSaveException` / `FolderPickerException` ("No active window found") as on .NET 10, instead of opening a dialog over a hidden window.
  - An app with no windows no longer gets an `ArgumentOutOfRangeException`, and .NET MAUI embedded in a WinUI app no longer gets a false "No active window found".
  - Canceling the `CancellationToken` closes the open save or folder dialog and returns a canceled result, as on .NET 10, instead of waiting until the person closes the dialog. If the person has the "Confirm Save As" prompt open, the save ends canceled once they answer it, and nothing is written.
  - Picks on the same window now take turns: a pick that starts while another `FileSaver` or `FolderPicker` dialog is open on that window waits until that dialog closes, and canceling its token ends the wait with a canceled result.
  - A cancel can still close a dialog that other code opened on the same window during the canceled pick, such as the app's own message box, because nothing marks a picker dialog as the toolkit's.

</details>

</dd></dl>

</details>

<details><summary>Maps</summary>

<dl><dd>

<details><summary>API</summary>

- **`CommunityToolkit.Maui.Maps` is removed.** There is no .NET 11 version of the package; `UseMauiCommunityToolkitMaps`, its `AppBuilderExtensions` and `MapHandlerWindows` no longer exist. See Setup below.

</details>

<details><summary>Setup</summary>

- **Change the package and the startup call.** Remove the `CommunityToolkit.Maui.Maps` package, its `using CommunityToolkit.Maui.Maps;` directives and the `UseMauiCommunityToolkitMaps` call; reference the `Microsoft.Maui.Controls.Maps` package directly (the toolkit package referenced it for you) and call `builder.UseMauiMaps()` on every platform.
- On Windows also call `builder.ConfigureEssentials(essentials => essentials.UseMapServiceToken("YOUR_AZURE_MAPS_SUBSCRIPTION_KEY"))`, because there the map is the WinUI 3 `MapControl` backed by Azure Maps and shows no map data without a valid key.
- On Windows, .NET MAUI's `Map` has no `IsShowingUser`, no polygons, polylines or circles in `MapElements`, no pin labels or info windows, and no `MapClicked`; `MoveToRegion`, the `Street`, `Satellite` and `Hybrid` map types, traffic, scrolling, zooming and pins work.
- See https://learn.microsoft.com/dotnet/maui/user-interface/controls/map?view=net-maui-10.0 and https://github.com/CommunityToolkit/Maui/issues/3190.

</details>

</dd></dl>

</details>

<details><summary>MathExpressionConverter and MultiMathExpressionConverter</summary>

<dl><dd>

<details><summary>Behavior</summary>

- **The expression syntax is culture-invariant.** Numbers in the expression always use `.` and every function name works in every culture; before, `3.5` meant 35 under de-DE and threw under fr-FR, and names containing `I` (`PI`, `IF`, `MIN`, `SIN`, `INT`, `CEILING`, ...) failed under tr-TR and az.
- String inputs and `str()`/`len()` use the culture the binding passes (see All packages).
- Quoted strings in the expression are values: they convert with the binding's culture, like the bound inputs, and are lowercased with invariant rules (under tr-TR `"I"` becomes `"i"`, not `"ı"`).

</details>

</dd></dl>

</details>

<details><summary>Source generators</summary>

<dl><dd>

<details><summary>Smaller changes</summary>

- **`[BindableProperty]` and `[AttachedBindableProperty]`: the generated code no longer depends on the build machine's culture.** On a Turkish or Azerbaijani machine an `internal` class generated `ınternal partial class` and a read-only `IsBusy` generated `ısBusyPropertyKey`; in comma-decimal and some other cultures, numeric default values generated invalid literals such as `3,1400000000000001` or `−1` (U+2212). All of these broke the app's build. Documentation comments in the generated code also use CRLF on every build machine.

</details>
